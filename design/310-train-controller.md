## TrainController

`TrainController` is a multi-module train computer that mirrors a real-world cab and on-board control system. It is one entity per train, but internally it is composed of 10 discrete sub-modules organized into three layers — input, compute, output. Code that touches one sub-module should not need to load the others.

**Sub-modules and where to find them in this chapter.**

*Input layer — data feeds into the controller:*

- **Operator command surface** — queue and drain order plus the setter / queue methods themselves: `controller.commands.set_cab(...)`, `controller.commands.set_mode(...)`, `controller.commands.set_manual_mode_type(...)`, `controller.commands.set_handle(...)`, `controller.commands.set_manual_power_percent(...)`, `controller.commands.power_on_cmd()`, `controller.commands.power_off_cmd()`, `controller.commands.enqueue_command(...)`, plus `controller.eb.activate()` and `controller.eb.release()`. Lives in `train_controller/commands.py` (class `OperatorCommands`); operator-side configuration state is accessed externally as `controller.commands.cab`, `controller.commands.control_mode`, `controller.commands.command_inbox`, and `controller.commands.drain_order`. The setter / queue methods orchestrate writes across multiple sub-modules (eb, ato, manual, route_hooks, physics_sync, ops) through the controller back-reference. See **Power/cab/mode command contracts** and **Driver/operator inputs** below.
- **Path plan projection** — live read-only projection of the dispatcher-owned `Path` into `received_path_plan`. Lives in `train_controller/path_projection.py` (class `PathProjection`). No owned fields — every read recomputes from `path_dispatcher.get_active_path(train_id)` (or other live sources) and auto-flips to `None` when the dispatcher transitions the path away from `ACTIVE`. Accessed externally as `controller.path_projection.received_path_plan`, `controller.path_projection.assigned_path_id`, `controller.path_projection.ato_path_id`, `controller.path_projection.ato_destination_block_id`, `controller.path_projection.path_backed_run_active`, `controller.path_projection.get_path_tiles()`, and `controller.path_projection.get_live_path_data()`. See **received_path_plan schema**, **Dispatcher/route-executor inputs**, and **route/dispatcher command contracts** below.
- **Physics sync** — `current_span` and `current_speed_kmh` storage; `on_physics_updated()` handler; `ControllerProgressReport` generation. Lives in `train_controller/physics_sync.py` (class `PhysicsSync`); accessed externally as `controller.physics_sync.current_span` and `controller.physics_sync.current_speed_kmh`. The orchestrator `controller.on_physics_updated(span_update)` stays flat on the façade because `TrainPhysics` invokes it directly and it drives cross-sub-module work (reactive state transitions, progress-report build). Each call **returns** one `ControllerProgressReport` directly to `TrainPhysics`, which collects them in callback order and returns the list from `TrainPhysics.tick(...)` to `SimulationController` for the same-transaction local progress buffer; there is no `queued_progress_reports` mailbox on the controller. See **TrainSpan schema** and **Read accessors** below.
- **Route hooks** — external entry points called by other components: `enter_station_dwell()`, `finish_dwell()` (from `RouteExecutor`); `on_path_complete()` (from `PathDispatcher`). Lives in `train_controller/route_hooks.py` (class `RouteHooks`); owns the four Phase-3 retained latches bundled under `PhaseLatches`. Accessed externally as `controller.route_hooks.phase_latches` (and the `set_*` writer helpers on that aggregate per the **Latch table**). The orchestrator entry-point methods (`enter_station_dwell`, `finish_dwell`, `on_path_complete`) stay flat on the façade because they are direct external callbacks; they delegate to this sub-module when latch writes are needed. See **route/dispatcher command contracts** and **Completion ownership and timing** below.

*Compute layer — the on-board computers:*

- **Operational state machine** — `state` field and transitions (`OFF` / `READY` / `RUNNING_MOVING` / `RUNNING_AT_STATION`). Lives in `train_controller/ops.py` (class `OperationalStateMachine`); accessed externally as `controller.ops.state`, `controller.ops.handle_position`, and `controller.ops.handle_reason` (diagnostic). State-transition methods, the canonical stopped predicate `is_stopped()`, and related predicates (`is_recovery_clean`, `active_conditions`, `power_on`) stay on the façade because they orchestrate writes across multiple sub-modules. See **Controller state machine**, **Controller tick order**, and the **Allowed `(state, cab)` pairs** table.
- **ATC Computer** — live `lookahead` computation, ATC speed-limit application, overspeed-to-EB escalation. Lives in `train_controller/atc.py` (class `ATCComputer`); accessed externally as `controller.atc.speed_limit` (cached cap), `controller.atc.clearance_ahead_cm` (cached clearance), `controller.atc.current_block_speed_limit` (cached block cap), `controller.atc.safety_margin_cm` (tunable), `controller.atc.signal_lookahead_blocks` (tunable scan depth), plus the recompute helpers `controller.atc.clearance_ahead()`, `controller.atc.speed_limit_now()`, `controller.atc.speed_limit_with_code()`, `controller.atc.is_caution_ahead()`, `controller.atc.is_approaching_yellow_signal()`, `controller.atc.is_signal_red_for_block(block_id)`, `controller.atc.effective_safety_margin()`, and `controller.atc.calculate_authority_boundary_limit()`. The lookahead build itself is owned by `LookaheadBuilder` in `lookahead_builder.py`. See **Lookahead is a pure derived value**, **canonical lookahead payload**, **ATC speed limit**, and **Speed curves** below.
- **ATO Computer** — handle-selection / curve-tracking / braking-notch logic, `ato.running` lifecycle, and depart-in-ATO acceptance. Lives in `train_controller/ato.py` (class `ATOComputer`); accessed externally as `controller.ato.running` (run-active flag), `controller.ato.info` (destination snapshot), `controller.ato.debug` (per-tick debug payload), `controller.ato.go()` / `controller.ato.stop()` (run lifecycle), `controller.ato.compute_handle(delta_seconds)` (per-tick handle selection), `controller.ato.compute_info()`, `controller.ato.sample_curve_at(curve, distance_cm, key)`, `controller.ato.simulate_forward(speed, handle, distance_cm, dt)`, `controller.ato.calculate_power_notch(...)`, and `controller.ato.calculate_braking_notch_for_speed(...)`. The module-level `rate_limit_handle(...)` helper lives in the same file. See **`ato.running` meaning and lifecycle** and **ATO handle calculation** below.
- **EB Workflow** — `eb.active`, EB activation effects, release contract, dwell exception. Lives in `train_controller/eb.py`; accessed as `controller.eb.active` (latch), `controller.eb.activate()` (operator-issued EB), and `controller.eb.release()`. The canonical home is the **EB workflow state machine** table in the Core Runtime Loop section; controller-side tick handling appears in **Controller tick order** below.
- **Manual driving** — `simulation` and `power_percent` submode behavior; `handle_position`, `manual.manual_power_percent`. Lives in `train_controller/manual.py` (class `ManualDriving`); accessed externally as `controller.manual.manual_mode_type` and `controller.manual.manual_power_percent`. The operator-facing setters `set_manual_mode_type(...)` / `set_manual_power_percent(...)` live on the operator command surface and write through to these fields. See **Manual mode and movement-authority boundary** below.

*Output layer — what the computer writes:*

- **Notification emission** — `command_result` per drained command and diagnostic notifications via `NotificationCenter`. The canonical notification surface is the **Runtime notifications** subsection in the Core Runtime Loop section. The per-controller toast queue (read by the frontend via `GET /api/trains/<id>/notifications`) lives in `train_controller/notifications.py`; controller-internal writers call `self.notifications.emit(msg)`, and the frontend drains via `controller.notifications.get_and_clear()`.

The Phase-3 latches owned by `TrainController` live nested under `TrainController.route_hooks.phase_latches: PhaseLatches` (fields: `path_cancel_request`, `route_abort`, `power_off`, `route_deactivate`) and are documented in the **Latch table** in the Core Runtime Loop section. `TrainController` owns the in-memory storage; the Latch Table is the single canonical home for writers, helpers, consumers, gating predicates, and lifecycle.

**Module boundaries.** These rules consolidate the "only X writes Y" constraints that apply across the chapter:

1. The Operational state machine is the only writer of `state`.
2. The EB Workflow is the only writer of `eb.active`.
3. The ATC Computer is the only computation site for `lookahead`.
4. Phase-3 latches are written only through the writer-helpers listed in the **Latch table** preamble; no sub-module assigns latch fields directly.
5. The Manual driving sub-module is the only writer of `handle_position` and `manual.manual_power_percent`. The EB Workflow may also write `handle_position = EB` as part of the canonical EB activation effects; that exception is named in the EB workflow state machine.
6. The Operator command surface is the only entry point for external operator commands. No external caller invokes ATC, ATO, EB, or manual driving sub-modules directly.

**Data flow per tick.**

- *Input:* the Operator command surface drains queued commands at the start of `TrainController.tick(...)`; the Path plan projection refreshes on every read of `received_path_plan`; Physics sync absorbs `PhysicsSpanUpdate` from `TrainPhysics.tick(...)`; Route hooks fire when `RouteExecutor` or `PathDispatcher` calls them.
- *Compute:* the Operational state machine evaluates reactive transitions; the ATC Computer computes `lookahead`; the ATO Computer (in ATO mode) or Manual driving (in manual mode) produces the active command; the EB Workflow can override the result at any step.
- *Output:* Notification emission flows to `NotificationCenter`; Phase-3 latches are written when accepted commands or in-tick escalations need deferred dispatcher cancellation; controller-state writes land on the canonical retained fields.

**Controller state**

- `TrainController` owns live power/cab state: `state` (canonical operational state, including `OFF`), active cab selection, and the live direction selection implied by that cab. The convenience read `power_on` is derived from `state != "OFF"`; it has no separate writer. These are not re-synced from `Train` on every tick.
- `TrainController` owns the train's live physical span and speed. `TrainPhysics.tick(...)` computes movement and emits `PhysicsSpanUpdate`; `TrainController.on_physics_updated(...)` is the normal writer that applies the new span/speed to controller-owned storage. `Train` itself does not store live position/span.
- Add `manual.manual_mode_type`, such as `simulation` or `power_percent`.
- `TrainController.travel_direction` is a **read-only derived value** computed each time it is read from `(self.cab, self.current_span)`. There is no stored field and there are no writers. The mapping rule: the cab's physical end (`end_a` or `end_b` per `TrainSpan`) is the head, and `travel_direction` is the network-frame direction pointing from the opposite physical end through the cab end and onward into the next span resource ahead. When no next span resource exists ahead of the cab end (e.g. the cab end is at a track-end / dead-end / disabled-resource boundary, or the consist sits on a single tile with no live forward connectivity), `travel_direction` is the network-frame direction outward through the cab edge of the cab end's tile. This rule depends only on consist-and-cab geometry, not on `received_path_plan`. When `self.cab is None`, the value is `None`. Successful writes to `cab` (`TrainController.commands.set_cab(...)`, `TrainController.depart()` auto-cab-selection) only write `cab`; they do not "atomically update" `travel_direction` because there is no field to update — the next read of `travel_direction` recomputes from the new cab.
- Add `manual.manual_power_percent` for `power_percent`-mode manual control. In v1 this is an integer `0..100` voltage-style command rather than a signed traction/brake command.
- Add `phase_latches.power_off: bool` as a stopped-only shutdown latch set by `TrainController.commands.power_off_cmd()` during the tick-entry command drain inside `TrainController.tick(...)`, and consumed by the later eligible Phase 3 OFF cleanup. It is the canonical handoff that moves power-off from command acceptance into the standard per-train phase workflow.
- `TrainController` owns the per-train Phase-3 retained latch / flag aggregate in v1. The aggregate is `phase_latches: PhaseLatches`, with the four fields `path_cancel_request`, `route_abort`, `power_off`, and `route_deactivate`. `ControllerProgressReport` values are not retained controller fields; they are returned into `SimulationController`'s same-transaction local progress buffer and drained by Phase 3 before the train transaction ends. The retained-field schema below lists `phase_latches` as a single field; the four nested fields are documented inside the **Latch table**. Dwell entry is NOT a flag — it is a state-machine transition driven by route state and controller state inside `TrainController.tick(...)`.
- Define the `READY` trigger explicitly: `READY` is the controller's state when the train is powered on and stopped, regardless of cab selection. A controller enters `READY` from `OFF` when power is turned on. Selecting or deselecting a cab while stopped keeps the controller in `READY`. Route authority may still be assigned while a cab is unselected, and `RouteExecutor` must not treat the absence of a cab as a blocker for `create_path(...)`. `TrainController.depart()` accepts authority per its canonical contract; auto-cab selection on success is part of that contract and is not restated here. Manual input may move the train even before `depart()` has been accepted (controller still in `READY`), but only when `received_path_plan is not None` so the canonical lookahead in step `22a9` exposes a path-bound ATC limit at distance 0; without a live path the no-authority empty payload sets `atc_limit = 0` at distance 0 and ATC holds the train at rest until a route assigns authority. Pre-depart manual movement cannot satisfy path stop-completion until `TrainController.depart()` has accepted that authority and the controller has transitioned to `RUNNING_MOVING`. Such pre-depart manual movement may still produce head-entry route progress such as `task_kind == "waypoint"` consumption; only stop-completion remains depart gated. The unsupported exception is same-tile synthetic movement with no cab selected: dispatcher rejects that request before any authority is stored.
- Keep manual driving as `control_mode == manual`; do not keep a separate `MANUAL` operational state.
- `assigned_path_id`, `ato_path_id`, and `ato_destination_block_id` are computed read-only properties on the path-projection sub-module (`controller.path_projection.assigned_path_id`, `controller.path_projection.ato_path_id`, `controller.path_projection.ato_destination_block_id`). They are derived live from `received_path_plan` per the alias mapping below; they are not stored controller fields and have no writers. There is no top-level `controller.assigned_path_id` shortcut — every caller goes through the sub-module.
- Add `received_path_plan` as the controller's read-only live movement-authority projection over the active dispatcher-owned path.
- `received_path_plan` is not stored controller state and has no writer. `PathDispatcher` owns the underlying `Path`; `TrainController` reads the projection and must not mutate path ownership or lifecycle.
- `TrainController` is also the canonical query and storage home for the train's current occupied span. The live span is produced by `TrainPhysics` and written into `TrainController.physics_sync.current_span`; block/switch resources still carry their own physical `occupied_by` ownership, but tile-level ends and ordered occupied tiles live on the controller span rather than on `Train`. `RouteExecutor` and `PathDispatcher` ask the controller for one cab-independent physical span read instead of deriving it independently from `Train`. That span read must expose the ordered occupied span in physical order (`occupied_blocks` and `occupied_tiles`) plus the two explicit physical end locators needed for later ordering comparisons. The occupancy list is the block-level ownership view; the end locators are the tile-level precise geometry view. It does not depend on a currently selected cab.
- Exception: same-tile synthetic movement without a selected cab remains unsupported in v1. `PathDispatcher.create_path(...)` should reject that request before an authority record is stored; `TrainController` does not infer or invent the cab direction for that case after the fact.

- The table above is the canonical retained controller field set for v1. If a field is not in this table or in a later canonical payload schema, it should not remain as an independently written live controller field.

- **`ControllerCondition` set** (canonical home; referenced elsewhere by name). `ControllerCondition` is the canonical enum of currently-active controller-state conditions used to express recovery and create-eligibility predicates. v1 values:

  - `HAS_AUTHORITY` — `received_path_plan is not None`
  - `EB_LATCHED` — `eb.active == True`
  - `POWER_OFF_PENDING` — `phase_latches.power_off == True`
  - `PATH_CANCEL_PENDING` — `phase_latches.path_cancel_request is not None`
  - `ROUTE_ABORT_PENDING` — `phase_latches.route_abort == True`
  - `ROUTE_DEACTIVATE_PENDING` — `phase_latches.route_deactivate == True`

  `TrainController.active_conditions` is a derived `FrozenSet[ControllerCondition]` computed each read from the controller's stored fields per the mapping above. Not a stored field; no writers.

  `TrainController.is_recovery_clean` (derived `bool`): `state == READY` AND `active_conditions` contains none of `{HAS_AUTHORITY, EB_LATCHED, POWER_OFF_PENDING}`. This is the canonical "controller has reached the stopped recovery state" predicate. Other sites cross-reference it by name and must not restate the conjuncts.

  `RouteExecutor.is_clean_for_create(train_id)` (derived `bool`): `controller.is_recovery_clean` AND `active_conditions` contains none of `{PATH_CANCEL_PENDING, ROUTE_ABORT_PENDING, ROUTE_DEACTIVATE_PENDING}` AND `run.path_cancelled is False`. This is the canonical "Phase 1 may run the create branch" predicate.

  Adding a new latch in a future revision means adding one `ControllerCondition` value plus one mapping line — every existing predicate site automatically picks up the new condition.

- **Allowed `(state, cab)` pairs.** The relationship between `state` and `cab` is structurally constrained but enforced by the `set_cab(...)` and `power_off_cmd()` writers. The legal combinations are:

  | `state` | `cab` |
  | --- | --- |
  | `OFF` | `None` |
  | `READY` | `None` or `"A"` or `"B"` |
  | `RUNNING_MOVING` | `"A"` or `"B"` |
  | `RUNNING_AT_STATION` | `"A"` or `"B"` |

  Any other combination is a contract violation. Readers needing cab membership read `cab` directly; the state alone does not encode it.

**Lookahead is a pure derived value**

`TrainController.lookahead` (and any equivalent accessor such as `TrainController.get_lookahead()`) is computed each time it is read from `(current_span, cab, received_path_plan, network_state, signals, current_speed_kmh, eb.active)`. `received_path_plan` supplies the ordered authorized corridor; speed limits, block/switch state, signal-derived diagnostics, and physical position are resolved from the authoritative network/controller state rather than copied into the controller authority payload. There is no stored field, no per-tick cache, and no separate "pre-physics" / "post-physics" copies. Layers that read lookahead receive the live result. (Lookahead caching is Out of Scope; see the **Out of Scope** section.)

**Controller state machine**

**`READY` state** (referenced elsewhere by name): the controller's `READY` state means powered, stopped, not dwelling, regardless of cab selection. Other sites must cross-reference `state == READY` and must not invent additional substate names for it.

| State | Meaning | Canonical entry triggers | Canonical exits |
| --- | --- | --- | --- |
| `OFF` (`414b`) | Power off | Phase-3 power-off cleanup consuming `TrainController.phase_latches.power_off` from a stopped powered state; startup default | `TrainController.commands.power_on_cmd()` |
| `READY` (`601a`) | Powered, stopped, `state != RUNNING_AT_STATION`. Cab may or may not be selected. | `TrainController.commands.power_on_cmd()`; post-path `TrainController.on_path_complete()`; successful no-authority stop after cancellation/revocation; `TrainController.eb.release()`; `TrainController.finish_dwell()`; reactive speed-based evaluation inside `TrainController.on_physics_updated(span_update)` when the just-written speed satisfies `TrainController.is_stopped()` and the train has no live authority (no-authority braking completion path, both ATO and manual). A driver in manual mode who voluntarily stops under positive clearance with live authority remains in `RUNNING_MOVING` per the next row. See the **Reactive speed-based state evaluation** bullets below for the full predicate set. (`TrainController.commands.set_cab(...)` while in `READY` is not a state transition — it updates `cab` and leaves `state == READY`.) | `TrainController.depart()` → `RUNNING_MOVING`; reactive speed-based evaluation inside `TrainController.on_physics_updated(span_update)` when the just-written speed satisfies `not TrainController.is_stopped()` (see below); `TrainController.enter_station_dwell()`; `TrainController.commands.power_off_cmd()` |
| `RUNNING_MOVING` (`185a`) | Depart accepted for the current authority. The train may be physically moving, or stopped at zero ATC clearance under the same live authority while waiting for clearance / authority extension. `RUNNING_MOVING` is the canonical "depart-accepted" indicator used by stop-completion eligibility and other readers. | `TrainController.depart()` acceptance; reactive speed-based evaluation inside `TrainController.on_physics_updated(span_update)` when the controller observes `not TrainController.is_stopped()` while in `READY` (rare manual edge case: a driver pre-rolls before depart was issued; once depart is accepted the controller transitions). | `READY` on post-path completion or no-authority stop; `RUNNING_AT_STATION` only through route-owned dwell entry after confirmed arrival; reactive speed-based evaluation to `READY` inside `TrainController.on_physics_updated(span_update)` when a train reaches the canonical stopped predicate without live authority; stopped-only operator commands accepted while `is_stopped()` is true: `set_cab(...)` → `READY`, `set_mode(...)` → `READY`, `power_off_cmd()` → writes `phase_latches.power_off`, with Phase-3 power-off cleanup exiting through `READY` to `OFF` |
| `RUNNING_AT_STATION` (`90c4`) | Route-managed dwell at a confirmed stop task | `RouteExecutor.tick_train_phase1(...)` dwell-entry step calls `TrainController.enter_station_dwell()` when the next non-finished task on the directed walk has `task_kind == "dwell"`. The controller does not detect dwell entry on its own; it never reads `RouteRun`. | `TrainController.finish_dwell()` (called by `RouteExecutor.tick_train_phase1(...)` dwell-complete step) → `READY`. EB during dwell does NOT exit `RUNNING_AT_STATION`: `TrainController.eb.activate()` is accepted and sets `eb.active = True`, but state remains `RUNNING_AT_STATION` and the dwell timer keeps running. `TrainController.eb.release()` from this state clears `eb.active = False` and stays in `RUNNING_AT_STATION`. `TrainController.commands.set_cab(...)` and `TrainController.commands.set_mode(...)` from `RUNNING_AT_STATION` apply their side effects (clear `ato.running`) but state stays `RUNNING_AT_STATION`. `power_off_cmd()` → writes `phase_latches.power_off`; Phase-3 power-off cleanup calls `RouteExecutor.remove_train_route_run(...)` which calls `finish_dwell()` to exit dwell before OFF teardown. |

- **Reactive speed-based state evaluation**: `TrainController.on_physics_updated(span_update)` evaluates state-machine transitions synchronously after writing the new `current_speed_kmh` and before building the `ControllerProgressReport`. The transition fires in the same tick that physics produces the speed change, so callers do not have to wait one tick to observe it. All speed comparisons here key on the canonical `TrainController.is_stopped()` predicate (per the **Units contract**), never on raw `current_speed_kmh` arithmetic. The reactive evaluation only applies when `state in {READY, RUNNING_MOVING}`; in `OFF` and `RUNNING_AT_STATION` it is a no-op (an unpowered drifting train or a dwelling train never reactively flips state — `OFF` exits only via `power_on_cmd()`, and `RUNNING_AT_STATION` exits only via `finish_dwell()` / `remove_train_route_run(...)`). The rules are:
  - If `state == READY` and `not TrainController.is_stopped()`: transition to `RUNNING_MOVING`. This is one of two canonical state-machine transitions into `RUNNING_MOVING` (the other is a successful `TrainController.depart()` call); both are equally legitimate first-class transitions. After this transition, if `control_mode == "ato"` and `received_path_plan is not None`, call `TrainController.ato.go()` — the canonical helper that sets `ato.running = True` per the **`ato.running` meaning and lifecycle** section; both the `depart()` path and this reactive path route through it so neither duplicates the precondition check. This rule covers the case where a manual driver pre-rolls under live authority before Phase 1's `depart()` lands, the case where ATC clearance returns under live authority and physics resumes motion before the next Phase 1 tick, and any other path that legitimately produces motion from `READY`.
  - If `state == RUNNING_MOVING` and `TrainController.is_stopped()` and the train has no live authority: transition to `READY`. This is the no-authority braking completion path. While live authority still exists and the train is stopped, the controller stays in `RUNNING_MOVING`; clearance may return and movement may resume without a fresh `depart()` call.
  - `RUNNING_MOVING` with `TrainController.is_stopped() == True` under live authority where clearance is positive (driver simply stopped the train manually) stays in `RUNNING_MOVING`; the canonical stopped predicate alone does not exit `RUNNING_MOVING` when the driver has voluntarily stopped under positive clearance.
  - `RUNNING_MOVING` with `current_speed_kmh == 0` where the ATC limit is zero under live authority — a best-effort truncated path whose `authority_end_block_id` is short of the route-owned armed stop target, and `extend_path(...)` returned `blocked_no_growth` — also stays in `RUNNING_MOVING` (see tick step `90d3`). `is_stopped() == True` alone does not exit `RUNNING_MOVING` while live authority exists, regardless of whether the stop is voluntary (positive clearance) or ATC-forced (zero clearance). In both cases, clearance may return when the path extends or conditions change, and movement may resume without a fresh `depart()` call.
- The state machine above is the single canonical operational-state contract. Shared logic must not introduce additional live route/runtime state enums for path completion or cancellation recovery in v1.
- **`RUNNING_AT_STATION` invariant**: `received_path_plan is None` whenever `state == RUNNING_AT_STATION`. Path completion (`PathDispatcher.try_complete_active_path(...)`) transitions the `Path` to `COMPLETED` in Phase 3; only after that transition does Phase 1's dwell-entry step (`3a37`) fire and call `enter_station_dwell()`. No code path may call `enter_station_dwell()` while a `Path` with `status == ACTIVE` still exists for this train. This invariant is the structural basis for the EB-during-dwell skip of `phase_latches.path_cancel_request` (row `0a8e` of the EB workflow table): because no live path exists during dwell, no path cancellation latch needs to be written.
- Stopped-only operator commands (`power_off_cmd()`, `set_cab(...)`, and `set_mode(...)`) may be issued from any physically stopped controller state. In v1 they disengage any active ATO run and land in `READY` (or `OFF` after pending power-off cleanup); they do not cause automatic movement just because clearance later returns or dwell later finishes.
- Stopped recovery commands transition to `READY` (regardless of cab); powered off remains `OFF`.

**`ato.running` meaning and lifecycle**

- `ato.running` means "an ATO run is currently in progress": the train has been commanded to move under ATO via `TrainController.depart()` / `TrainController.ato.go()`, and that run has not yet been ended by arrival-at-dwell, path completion, authority clear, EB, or any stopped-state command (power / cab / mode). It is a **run-active** flag, not a **mode** flag. The mode flag is `control_mode` (`ato` vs `manual`), which says "what kind of driving the controller is configured for"; `ato.running` says "is an ATO run currently driving the train." A train in ATO mode is not necessarily `ato.running`: before the first `depart()`, between runs, during dwell, and after any run-ending event, `control_mode == ato` but `ato.running == False`. When the train is stopped with zero ATC clearance but the same live authority still exists (i.e. still in `RUNNING_MOVING` with `current_speed_kmh == 0`), the run has not ended — `ato.running` stays `True` so the controller auto-resumes when clearance returns. A train in manual mode is never `ato.running`.
- `ato.running = True` is set by the canonical state-machine transition into `RUNNING_MOVING` whenever `control_mode == "ato"` and `received_path_plan is not None` at the moment of transition. This applies to both transition triggers: a successful `TrainController.depart()` acceptance (which calls `TrainController.ato.go()`) AND the reactive speed-based evaluation entering `RUNNING_MOVING` from `READY`. Both transitions converge on the same write; `ato.go()` remains the canonical helper that performs the write so callers do not need to duplicate the precondition check. No other command, tick handler, or callback flips this flag to `True`. In particular, `TrainController.commands.set_cab(...)`, `TrainController.commands.set_mode(...)`, `TrainController.eb.release()`, `TrainController.on_path_complete()`, `TrainController.enter_station_dwell()`, and `TrainController.finish_dwell()` never set `ato.running = True`.
- `ato.running` has exactly one writer: `TrainController`. Neither `RouteExecutor` nor `PathDispatcher` nor any train-side mirror writes this flag directly; train-running state is not a route executor's concern. `ato.running = False` is set by `TrainController` on every canonical run-ending event: successful start of dwell (`enter_station_dwell()`), controller path completion (`on_path_complete()`), authority clear (observed inside `TrainController.tick(...)` when `received_path_plan is None` while `ato.running` was previously `True`), EB activation (inside the controller's EB entry path), `power_off_cmd()` immediately on acceptance before later OFF cleanup, `set_cab(...)`, and `set_mode(...)`. Resuming ATO after any of these events requires another `depart()` / `ato.go()` acceptance.
- A zero-ATC-clearance hold under live authority does not by itself clear `ato.running`. The controller stays in `RUNNING_MOVING` with `current_speed_kmh == 0`, and the flag stays `True` so that when the distance-0 ATC limit becomes positive again the controller resumes forward motion without a fresh departure decision. Only the run-ending events listed above (path completion, dwell entry, EB, authority clear, power/cab/mode changes) toggle `ato.running` back to `False`.
- Manual mode never sets `ato.running`. In manual, `TrainController.depart()` marks the current authority ready to go and does not call `ato.go()`; `ato.running` stays `False` throughout manual driving.

**Power/cab/mode command contracts**

- `TrainController.commands.power_on_cmd()` is the explicit `OFF -> powered` transition. It is valid only when power is currently off and is processed in the train's Phase-2 operator-command slot. When a train starts its transaction `OFF`, `SimulationController` skips that train's route Phase 1 because planning cannot run before command drain. The Phase-2 command slot still runs so power-on can be accepted. If `power_on_cmd()` succeeds, the controller is no longer `OFF`, so the transaction continues through the remaining controller logic, `TrainPhysics.tick(...)`, and the normal Phase 3 feedback/cleanup pass; only fresh route planning waits for a later Phase 1 tick. The controller transitions to `READY` regardless of cab selection.
- `TrainController.commands.power_off_cmd()` is valid only while the train is stopped, and it remains valid when `eb.active == True`. In the phase model it is a stopped-only controller command that validates acceptance during the tick-entry command drain inside `TrainController.tick(...)`, immediately disengages any active ATO run by setting `ato.running = False`, and calls `TrainController._apply_power_off_request()` (which sets `phase_latches.power_off = True` and — when a live path exists at write time — writes the inclusive `phase_latches.path_cancel_request` with `initiator = "power_off"` per the **Writer-helper rule**). It does not cancel dispatcher authority, clear EB, or remove route execution inline. The actual route/dispatcher teardown follows the **Power-off procedure**: Phase 3 step (c) commits the dispatcher cancel through `PathDispatcher.cancel_path(...)` and lets the ordinary cancellation workflow notify `RouteExecutor` while the route execution is still registered; step (e) then calls `RouteExecutor.remove_train_route_run(train_id)`, and only then transitions the controller to `OFF`, clears the active cab selection, clears any EB latch, and clears `phase_latches.power_off`. The controller turning off does not stop `TrainPhysics`; world physics continues to run.
- `TrainController.commands.set_cab(cab)` is valid only while the train is stopped (`is_stopped() == True`), which includes `RUNNING_AT_STATION` (dwell is a stopped state). If the requested cab equals the current cab (including same-letter no-op or `None == None`), `set_cab(...)` is a no-op success: it does NOT change controller state, does NOT disengage `ato.running`, and emits no notification beyond the ordinary `command_result` acknowledgement. Otherwise it disengages any active ATO run (`ato.running = False`) because cab selection is part of the depart-acceptance contract and changing cab invalidates the previous "ready to go" decision, and does not create motion or clear any currently assigned dispatcher authority. State-transition rule: when called from `RUNNING_AT_STATION`, `set_cab(None)` is rejected (`success=False` with diagnostic such as `"cannot deselect cab while dwelling"`) because `(RUNNING_AT_STATION, None)` is not a legal `(state, cab)` pair per the **Allowed `(state, cab)` pairs** table; setting a different non-`None` cab letter is accepted and the state stays `RUNNING_AT_STATION` (dwell is preserved; the side effects above still apply). When called from `READY`, the state stays `READY` (only `cab` changes). A change of cab from `RUNNING_MOVING` is rejected because the train is moving; the operator must stop first. If the selected cab points away from the current live authority, the controller must not rewrite that authority. Instead it rebuilds lookahead in the selected travel frame; if that frame has no forward authority, the distance-0 ATC limit becomes `0`, so ATC prevents wrong-direction movement under the mismatched cab choice. A fresh `TrainController.depart()` acceptance is required to re-arm departure.
- `TrainController.commands.set_mode(mode)` is valid only while the train is stopped (`is_stopped() == True`), which includes `RUNNING_AT_STATION`. It switches between `ato` and `manual`, disengages any active ATO run (`ato.running = False`), and does not create or clear dispatcher authority. `manual` is a control mode, not a separate operational state. State-transition rule: when called from `RUNNING_AT_STATION`, the state stays `RUNNING_AT_STATION` (dwell is preserved). When called from `READY`, the state stays `READY`.
- `TrainController.commands.set_manual_mode_type(mode_type)` is the canonical setter for `manual.manual_mode_type`. It is valid only while the train is stopped, powered, and `control_mode == manual`. Side effects: when entering `power_percent`, reset `handle_position` to neutral; when entering `simulation`, reset `manual_power_percent = 0`. It preserves cab selection and `received_path_plan`, and does not start movement. The construction default for `manual.manual_mode_type` is `simulation`. The frontend/API and editor/UI must expose this setter through the same operator-input route as `set_handle()` / `set_manual_power_percent()`.
- `TrainController.commands.set_handle()` accepts only when `control_mode == manual`, `manual_mode_type == simulation`, `state in {READY, RUNNING_MOVING}`, a cab is selected, and `eb.active == False`; otherwise it returns `success=False`. Handle input is rejected during dwell (`state == RUNNING_AT_STATION`) and when powered off — dwell has no live path for ATC to scaffold the handle command against, and OFF has no controller authority at all. `TrainController.commands.set_manual_power_percent(percent)` accepts under those same driver-input conditions except `manual.manual_mode_type` must be `power_percent`. It clamps `percent` to `0..100`, writes `manual.manual_power_percent`, preserves `received_path_plan`, and does not start movement by itself. `TrainController.commands.set_handle()` is rejected (`success=False`) when `manual_mode_type == power_percent`. `TrainController.commands.set_manual_power_percent()` is rejected (`success=False`) when `manual_mode_type == simulation` or when any of the shared acceptance preconditions fail.
- There is no separate `TrainController.set_travel_direction(...)` command in v1. Manual direction selection is only by cab selection through `TrainController.commands.set_cab(...)`.
- `TrainController.eb.activate()` is the canonical operator-issued EB command and intentionally has no other precondition: emergency means it must be available at all times. Its only acceptance gate is `eb.active == False` (idempotent rejection of a duplicate activation while EB is already latched). It is valid in any motion state, any operational state including `OFF`, with or without a cab, with or without a live path. On acceptance it performs the **canonical EB activation effects** defined in the **EB workflow state machine**. Exception while `state == RUNNING_AT_STATION`: the controller is dwelling and has no live path (`received_path_plan is None`), so no `phase_latches.path_cancel_request` is written (per row `0a8e` of the EB workflow table); state remains `RUNNING_AT_STATION`; the dwell timer keeps running and is not disturbed.
- `TrainController.eb.release()` accepts when `state != "OFF"`, `eb.active == True`, `TrainController.is_stopped() == True`, the controller's own `phase_latches.path_cancel_request` is `None` (the EB cancel latch has been consumed), and the controller's own `received_path_plan` is `None` (the pre-EB authority has transitioned out of `ACTIVE` in `PathDispatcher`). Otherwise it returns `success=False` and leaves controller state unchanged. This gate prevents same-command-drain EB activation/release from setting recovery latches before Phase 3 has committed the EB cancellation. The check uses only controller-owned fields; no dispatcher read is needed. On acceptance from `state == RUNNING_AT_STATION` (EB had been raised during dwell, no live path was ever cancelled), state stays `RUNNING_AT_STATION` and dwell timing is unaffected. On acceptance from any other powered state, follow the standard release behavior described in the EB workflow state machine.

**received_path_plan schema**

- This is the single canonical schema for the controller's active path-plan payload. Every producer/consumer should refer back to this subsection by name instead of restating the field list elsewhere.
- **Why this shape.** The controller's job is to brake to the live authority boundary using its safety margin and to compute speed restrictions live from the network and the authorized corridor. That work needs the corridor geometry (`resource_sequence`) and the boundary (`authority_end_block_id`); it does not need the dispatcher-side requested-target fields, which are a `PathDispatcher` completion-enforcement concern. Keeping the projection narrow lets the controller stay decoupled from dispatcher-side completion logic and lets `received_path_plan` regenerate as a pure read with no caching.
- `received_path_plan` carries exactly `path_id`, `resource_sequence`, and `authority_end_block_id` in v1. It is the controller's only active path-plan payload. `resource_sequence` uses the canonical **resource_sequence entry schema**, and each nested `path_tiles` slice uses the canonical **path_tile entry schema**, so the controller can extend lookahead along the actual geometry without reading `Train.current_path` and without inferring terminal-frame direction from tile coordinates alone. The requested target (`requested_destination_block_id`, `requested_destination_direction`) is stored on the dispatcher-owned `Path` record but is not included in `received_path_plan`; the controller does not see those fields. Completion enforcement against the requested target is internal to `PathDispatcher.try_complete_active_path(...)`.
- When the live authority already reaches the dispatcher-stored requested target, `authority_end_block_id` in `received_path_plan` equals `Path.requested_destination_block_id`; when the path is a best-effort truncated authority, `authority_end_block_id` is the temporary current boundary.
- `received_path_plan` does not carry a separate cab or head-side field. The ordered `resource_sequence` is the combined already-occupied physical span plus forward path authority in tail-to-authority order. "Tail" means the physical end of the current span farther from `authority_end_block_id`; "authority side" means the physical end closer to the destination and pointing into the path authority. When `TrainController.depart()` is asked to run in ATO or manual with no cab selected, it derives the cab by comparing `TrainSpan.end_a` and `TrainSpan.end_b` against that ordered seeded span and chooses the cab whose physical end is on the authority side. `end_a` is not a general preferred end in this model; it is only the final dead-heat tie-break when every authority-side comparison between the two physical ends remains exactly tied.
- `controller.path_projection.assigned_path_id`, `controller.path_projection.ato_path_id`, and `controller.path_projection.ato_destination_block_id` are computed reads derived from `received_path_plan`, not independently written runtime fields. The alias mapping is explicit in v1:
  - `path_projection.assigned_path_id := received_path_plan.path_id`
  - `path_projection.ato_path_id := received_path_plan.path_id`
  - `path_projection.ato_destination_block_id := received_path_plan.authority_end_block_id`
  Each returns `None` when `received_path_plan is None`. When `PathDispatcher` clears authority by transitioning `Path.status` to `COMPLETED`/`CANCELLED`, the controller's `received_path_plan` property returns `None` on its next read and all three disappear automatically.
- Keep `lookahead`, but make it a canonical pure derived value computed live on every read; it is the single canonical series used by ATC, ATO, UI, and monitor consumers.
- Target speed and ATC limit are reads from lookahead at distance 0; the controller does not store standalone `target_speed` or `effective_limit` scalars. The top-level `speed_limit_reason` field remains in the exported v1 payload shape for current UI/monitor consumers; its canonical source is the distance-0 lookahead speed-curve metadata.

**canonical lookahead payload**

- `TrainController.get_lookahead()` is the single canonical exported lookahead payload for ATC, ATO, UI, and monitor consumers. Every producer/consumer should refer back to this subsection by name instead of restating the field list elsewhere.
- **Why this shape.** Lookahead is the single read surface that fuses authority geometry, network state, signals, and current motion into one ordered forward projection. ATC, ATO, monitor UI, and stop-completion all sample from the same payload, so there is one place to add or change a forward-projected datapoint. Speed-curve metadata (including `atc_limit_reason_code`) lives on the same payload so that "why is the train holding at zero?" is answerable from one read instead of three. The empty/no-cab/no-train form preserves the same shape so consumers do not need to branch on payload variant.
- In v1, `get_lookahead()` carries exactly:
  - top level: `train_id`, `head_tile`, `head_distance_cm`, `travel_direction`, `cab`, `speed_limit_reason`, `lookahead`
  - nested `lookahead`: `blocks`, `signals`, `switches`, `stations`, `clearance_cm`, `safety_margin_cm`, `authority_boundary_delta_cm`, `speed_curves`
- `head_tile` is the current train head tile coordinate or `None` when unavailable. `head_distance_cm`, `clearance_cm`, `safety_margin_cm`, and `authority_boundary_delta_cm` are centimeters. `travel_direction` is the train's current forward travel direction in the same frame used by movement/traversal. `cab` is the currently selected cab or `None`.
- `blocks`, `signals`, `switches`, and `stations` are ordered forward projections for UI/debug consumers. They are informational read models only; control decisions come from the same payload's clearance and speed-curve data.
- `lookahead.stations` keeps the current compatibility payload name in v1, but each entry refers to a concrete physical platform ahead on the track, not to a logical multi-platform station group.
- Each `lookahead.blocks` entry carries exactly:
  - `id`
  - `name`
  - `state`
  - `start_cm`
  - `end_cm`
  - `length_cm`
  - `tile_count`
  - `speed_limit_kmh`
- Each `lookahead.signals` entry carries exactly:
  - `id`
  - `name`
  - `state`
  - `distance_cm`
- Each `lookahead.switches` entry carries exactly:
  - `x`
  - `y`
  - `name`
  - `position`
  - `distance_cm`
  - `locked`
  where `position` is `"main"` or `"diverging"` for the live switch alignment at that tile, and `locked` is the exported boolean monitor view of whether that switch currently has any future lock claim or train-owned protection claim that blocks conflicting acquisition.
- Each `lookahead.stations` entry carries exactly:
  - `platform_id`
  - `station_id`
  - `name`
  - `distance_cm`
  - `length_cm`
  - `tile_count`
  - `top_speed_kmh`
- `platform_id` in this compatibility payload is the concrete physical platform identifier on the track.
- `station_id` in this compatibility payload is the logical station-group identifier that owns that platform, or `None` when no station group exists. `station_id` must not be reused as the physical platform identifier anywhere.
- Each `lookahead.speed_curves` entry carries exactly:
  - `distance_cm`
  - `atc_limit`
  - `operational_limit`
  - optional `atc_limit_reason_code`
  - optional `atc_limit_reason_detail`
  The limit fields are in `km/h`.
- The canonical `atc_limit_reason_code` enumeration is defined here once. Every consumer (`is_stopped()` predicate, post-physics usable-authority stop check, no-authority braking diagnostic, monitor/UI display) cross-references this set by name and must not use arbitrary strings or redefine the values elsewhere:
  - `"authority_stop"` (`f169`) — zero-speed restriction at the safety-margin-adjusted end of live authority; the sole code that satisfies the usable-authority stop check for path completion
  - `"caution"` (`39ed`) — approaching or inside a caution zone (block in `CAUTION` state or forward block occupied)
  - `"obstruction"` (`05e9`) — an in-path resource conflict that blocks forward progress below safe clearance distance
  - `"no_authority"` (`7f1a`) — no live path authority; `atc_limit = 0` at distance 0 regardless of block geometry, so ATC holds a stopped train at rest and escalates a rolling train to EB
  - `"no_cab"` (`2ce5`) — no cab selected; ATC limit is zero regardless of authority
  - `"wrong_direction_cab"` (`a54f`) — selected cab points away from live authority direction; ATC limit is zero
  - `"eb"` (`c3ea`) — emergency brake latched; ATC limit is zero
- `atc_limit_reason_code == "authority_stop"` is the canonical reason code for the zero-speed restriction at the active stop/end-of-authority boundary. The controller stop-completion predicate must key on this code, not on arbitrary reason strings.
- `authority_boundary_delta_cm` is the live signed separation from the train head to the safety-margin-adjusted authority boundary in the same forward distance axis as the `speed_curves[*].distance_cm` samples and the authority-boundary projection helper. **Sign convention:** positive means the head is past the safety-margin boundary (overrun); negative means the head is still short of it. With a live path it is derived from `authority_end_block_id` plus the terminal frame; without a live path it is `0.0` because no authority boundary exists. It is diagnostic/control lookahead data, not a route-authored stop-position field.
- Consumers asking "what is the target speed right now?" sample `lookahead.speed_curves` at distance `0`: `operational_limit` at distance `0` is the controller target speed, and `atc_limit` plus its reason metadata at distance `0` is the controller ATC limit/reason. The top-level `speed_limit_reason` field remains part of the exported v1 payload shape for compatibility with current monitor/UI consumers.
- The empty/no-cab/no-train form must preserve this same top-level and nested key shape, with empty lists and zero distances instead of returning a different payload shape. If a compatibility producer cannot compute one of the nested boundary/safety fields on an empty payload, it should still emit the key with `0.0` rather than omitting it.

**Controller tick order**

1. `3ec8` — If no train, return immediately.
2. `01f2` — Drain queued operator commands as the first substep of `TrainController.tick(...)`. After that drain, if `state == "OFF"`, keep the controller in `OFF` and return from the controller tick's powered decision work; `SimulationController` still runs `TrainPhysics.tick(...)` and `TrainController.on_physics_updated(...)` for storage/physics continuity, but that callback must return no dispatcher/route progress reports and Phase 3 is skipped for that still-off transaction. If `TrainController.commands.power_on_cmd()` succeeded during the drain, the controller is no longer `OFF`, so `TrainController.tick(...)` continues into normal powered controller logic, `SimulationController` runs `TrainPhysics.tick(...)`, and Phase 3 runs normally for that same transaction. Route Phase 1 remains skipped only for the transaction that began while the train was `OFF`; route planning resumes on the next eligible tick.
2a. `a7d1` — **Authority-loss bookkeeping.** Immediately after the command drain and before any other powered substep, read `received_path_plan` once. If the property transitioned from non-`None` (last observation) to `None` since the last tick (because `PathDispatcher` transitioned `Path.status` out of `ACTIVE`) and `ato.running == True`, clear `ato.running = False`. This is the canonical site for the run-ending "authority cleared" event when no other run-ending event (EB, dwell entry, completion callback, cab change, mode change) already cleared it. The clear is idempotent; if `ato.running` was already `False`, this substep is a no-op. The controller does not re-arm or replan from this substep — fresh planning is the next eligible Phase 1's job.
3. `d483` — If emergency brake is active:
  - Re-apply the **canonical EB activation effects** defined in the **EB workflow state machine** if they have not yet been applied this tick (idempotent re-write of handle = `EB`, `ato.running = False`, and the `phase_latches.path_cancel_request(EB)` payload when a live path exists). Then early-exit the tick while EB remains latched.
  - Stay in the early-exit loop until the train has stopped.
  - Require explicit `eb.release()` to clear `eb.active`.
  - While `eb.active == True`, `TrainController.tick()` does not perform post-EB restart logic. `TrainController.eb.release()` owns the transition to the **`READY` state** (per the predicate defined in the Controller state machine subsection); that release step does not clear route-owned recovery state. The earlier EB activation already wrote `phase_latches.path_cancel_request(EB)`, which Phase 3 cancels and which sets `RouteRun.path_cancelled = True` via the cancellation callback. `RouteExecutor.tick_train_phase1(...)` (Phase 1) owns the route-deviation cleanup step and observes `path_cancelled` once the controller has reached the `READY` state.
4. `7a04` — (No-op in v1.) `TrainController.tick(...)` does not run any departure-handoff substep. `TrainController.depart()` is called directly by Phase 1 (or by an explicit operator confirmation handler) outside `TrainController.tick(...)`; on success it transitions the controller to `RUNNING_MOVING` and starts ATO only through `TrainController.ato.go()` when `control_mode == "ato"`. The controller does not write any `RouteRun` field — the canonical `task_runs[i].started_at` writers are `RouteExecutor` index-advance steps in Phase 1 (covered-task advance, dwell-entry) and the Phase 3 head-advance / stop-completion callbacks.
5. `293e` — (No-op in `TrainController.tick(...)` in v1.) The reactive speed-based state evaluation is owned by `TrainController.on_physics_updated(span_update)` and fires synchronously when physics writes the new speed (see the **Reactive speed-based state evaluation** bullets above the state-machine table). `TrainController.tick(...)` does not run a separate reactive-evaluation step — by the time the next tick begins, the previous tick's physics callback has already applied any READY↔RUNNING_MOVING transition and any associated `ato.go()` call.
6. `d237` — (No-op in v1.) Lookahead is a pure derived value computed live each time it is read; there is no separate consume/refresh step. Consumers below read `lookahead` directly when they need it.
7. `061a` — If no cab is selected, ATC limit is forced to zero and `lookahead` returns the canonical empty payload on every read.
8. `22a9` — Otherwise `lookahead` returns the canonical payload for the current state on every read:
  - With a received path plan, lookahead extends along the path to the current `authority_end_block_id` boundary adjusted by the controller safety margin.
  - Without a path plan, `lookahead` is the canonical no-authority empty payload (same top-level and nested shape as the no-cab case). `speed_curves` carries a single anchor at `distance_cm = 0.0` with `atc_limit = 0.0`, `operational_limit = 0.0`, and `atc_limit_reason_code = no_authority`. `blocks`, `signals`, `switches`, and `stations` are empty lists. `clearance_cm = 0.0` and `authority_boundary_delta_cm = 0.0`. The controller does not project forward through the train's current occupied block when no live path exists; movement authority is binary on `received_path_plan` per the **`received_path_plan` schema** rule that there is no second authority source.
9. `c4c2` — Build ATC state from `lookahead`, including structured reason metadata.
10. `914f` — Apply ATC overspeed logic.
11. `0a4e` — Calculate ATO info.
12. `8d18` — In ATO mode:
  - If `ato.running`, calculate handle with `ato.compute_handle(delta_seconds)`.
  - If not running and live authority still exists, choose braking handle toward zero and transition to the **`READY` state** once stopped. If live authority has been cleared while rolling, the no-authority EB escalation branch in step `826a` (lookahead becomes the no-authority empty payload, ATC overspeed at distance 0 raises EB) owns the behavior instead of this generic not-running branch.
13. `924d` — In manual mode, write a controller-owned command and let physics convert it to speed:
  - In `simulation` submode, store the driver's handle notch in `handle_position` and allow ATC to override with braking.
  - In `power_percent` submode, store the driver's percentage power in `manual.manual_power_percent` as an integer `0..100` and let physics map it through `SpeedProfile.power_speed_curve` when no braking override is active. **TrainSpan schema**

This is the canonical v1 shape of `TrainController.physics_sync.current_span` and the payload returned by `TrainController.get_current_span()`.

| Field | Type | Meaning |
| --- | --- | --- |
| `end_a` | `SpanEndLocator` | Stable physical end A of the consist. It is cab-independent and does not imply head/tail. |
| `end_b` | `SpanEndLocator` | Stable physical end B of the consist. It is cab-independent and does not imply head/tail. |
| `occupied_tiles` | `List[Tuple[int, int]]` | Tile-level coverage in physical order from `end_a` to `end_b`. |
| `occupied_blocks` | `List[str]` | Unique block IDs currently covered by the train, in first-seen `end_a` -> `end_b` order. |

`SpanEndLocator` carries exactly:

- `tile` — current tile coordinate for that physical end
- `entry_edge` — `"N"`/`"E"`/`"S"`/`"W"` edge used as the end's current in-tile distance frame
- `distance_cm` — precise in-tile distance from `entry_edge`, in centimeters

Consumers that need the forward/head side derive it from selected cab/travel state plus `end_a` / `end_b`; `TrainSpan` itself never relabels `end_a` or `end_b` as head/tail.

`PhysicsSpanUpdate` is the canonical payload from `TrainPhysics.tick(...)` into `TrainController.on_physics_updated(span_update)`. It carries exactly:

- `new_span: TrainSpan`
- `current_speed_kmh: float`
- `added_tiles: List[TileTraversal]` in physical traversal order for tiles newly covered by the updated span
- `removed_tiles: List[TileTraversal]` in physical vacate order for tiles no longer covered by the updated span

`TileTraversal` carries exactly:

- `tile_xy` — tile coordinate
- `entry_edge` — `"N"`/`"E"`/`"S"`/`"W"` traversal-frame entry edge
- `exit_edge` — `"N"`/`"E"`/`"S"`/`"W"` traversal-frame exit edge; for tail-vacated block tiles this is the vacated block's forward exit edge for the traversal by which the train left that block, which `TrainController` reads as the block tail-vacate `direction`
- `resource_type` — `"block"` or `"switch"` when the tile belongs to a known resource, otherwise `None`
- `resource_id` — block or switch ID for that resource, otherwise `None`
- `block_id` — owning block ID when applicable, otherwise `None`

`TrainPhysics` computes this delta by comparing the previous controller-owned span it read at the start of the movement step with the newly integrated span. `TrainController` is the only normal writer of the stored `current_span`: it applies `span_update.new_span`, derives resource entry/release observations from `added_tiles` / `removed_tiles`, packages them into one `ControllerProgressReport`, and returns that report for `SimulationController`'s same-transaction local progress buffer and later delivery to `PathDispatcher.on_controller_progress(report)`.

`TrainPhysics.tick(...)` must emit a `PhysicsSpanUpdate` on every tick, even when `added_tiles` and `removed_tiles` are both empty and the integrated `new_span` / `current_speed_kmh` are unchanged. When nothing changed physically, this is an explicit no-change callback. The always-callback rule keeps `TrainController.physics_sync.current_span` / `current_speed_kmh` canonical and gives Phase 3 a deterministic consume point for local progress consumption, the post-physics stop check, and latches such as `phase_latches.power_off`.

  | `ordered_blocks` | `Optional[List[str]]` | Ordered block IDs visited by the walk, with consecutive duplicate block steps collapsed only when they represent the same directed block traversal. `None` when `return_blocks=False`. |
  | `start_locator` | `GraphLocator` | The resolved tile-precise start locator used by the graph search, including block/tile membership and optional in-tile position when supplied by the caller. |
  | `terminal_locator` | `GraphLocator` | The resolved tile-precise terminal locator reached by the candidate. |
  | `terminal_block_id` | `str` | Block ID of the terminal block reached by the candidate. |
  | `terminal_block_direction` | `"forward" \| "reverse"` | Terminal block-relative traversal direction derived from the candidate's directed frame against `Block.ordered_tiles`. |
  | `terminal_frame` | `DirectedBlockFrame` | Terminal directed block frame, including path tiles plus `entry_edge` / `exit_edge` metadata needed by dispatcher/controller projection helpers. |
  | `tile_count` | `int` | Number of tile steps in the directed walk; first comparison key. |
  | `walk_length_cm` | `float` | Centimeter length along the directed walk; second comparison key. |
  | `candidate_rank` | `int` | Stable deterministic tie-break assigned by `RailwayPathfinder.query_graph_walks(...)` after `tile_count` and `walk_length_cm`; third comparison key. |

  Every caller that compares candidates must choose by `(tile_count, walk_length_cm, candidate_rank)`. `walk_length_cm` is the common physical-distance metric regardless of caller input type: a waypoint/station/platform input is first resolved into one or more concrete terminal `GraphLocator` values and compared by the same walk distance, while a direct block/tile input already supplies the terminal locator used for the same distance calculation. `candidate_rank` is only for exact ties after those graph metrics. It is assigned by the shared graph home using one deterministic ordering of the directed walk identity: ordered resource IDs, ordered tile coordinates, entry/exit edge sequence, terminal locator identity, and then any remaining stable insertion order from the graph query. Callers must not replace `candidate_rank` with waypoint-specific, UI-order, or layer-local heuristics. If those metrics still remain exactly tied across the remaining current-span end choices, use `end_a` as the final deterministic dead-heat tie-break outside `GraphWalkCandidate`; no other layer-local tie-break is allowed.

  | Field | Type | Meaning |

**Pathfinding-home migration**

- The current operational backend path search lives in `PathDispatcher.find_paths(start_block_id, end_block_id, train_id=None) -> List[PathSegment]` / `PathDispatcher._bfs_find_paths(...)`. That contract is insufficient for the v1 contracts above because it is block-to-block and distance-sorted only; it does not support direction-aware terminal rejection, locator-level (tile-precise) start positions, explicit switch-handling mode, the canonical `(tile_count, walk_length_cm, candidate_rank, final end_a dead-heat tie-break)` comparison rule, or measure-along-walk projection. The refactor must extend or extract that existing backend pathfinding home so it exposes at least:
  - `RailwayPathfinder.query_graph_walks(request: GraphWalkQuery) -> List[GraphWalkCandidate]` — direction-aware network-graph search that accepts a `GraphWalkQuery` request payload (defined below). It accepts tile-precise start and end locators (not just block IDs), skips disabled blocks/switches, either respects current switch state or searches topology-only according to `request.switch_handling`, rejects candidates whose terminal traversal does not satisfy `request.requested_destination_direction` or `Block.allowed_travel_directions`, and returns comparable walk candidates plus whichever ordered tile/block walk payload the request flags asked for.

  `GraphWalkQuery` carries exactly:

  | Field | Type | Meaning |
  | --- | --- | --- |
  | `start_locator` | `GraphLocator` | Tile-precise start locator. |
  | `end_locator` | `GraphLocator` | Tile-precise end locator. |
  | `switch_handling` | `"respect_current_state" \| "topology_only"` | Whether the search respects current `Switch.position` or searches topology-only for later acquisition. |
  | `requested_destination_direction` | `Optional["forward" \| "reverse"]` | Optional terminal direction filter; candidates whose terminal traversal does not match are rejected. |
  | `exclude_resources` | `Optional[Set[str]]` | Optional set of resource IDs to exclude from the search (used by retry / extension logic). |
  | `return_tiles` | `bool = True` | Whether to populate `GraphWalkCandidate.ordered_tiles`. |
  | `return_blocks` | `bool = True` | Whether to populate `GraphWalkCandidate.ordered_blocks`. |
  - `RailwayPathfinder.find_ordered_walk(...) -> Optional[GraphWalkCandidate]` — optional thin adapter over `RailwayPathfinder.query_graph_walks(...)` for callers that specifically need the chosen ordered walk payload.
  - `RailwayPathfinder.measure_along_walk(ordered_walk, locator_a, locator_b) -> float` — in-walk centimeter distance projection between two locators on an already-chosen walk, used by lookahead and platform-end pair comparison.
  - `RailwayPathfinder.get_reachable_endpoints(start_block_id, include_stations=True) -> List[str]` — reachability enumeration that returns every block (and optionally every station) topologically reachable from `start_block_id`. The walk steps tile-by-tile, so switch tiles do not act as graph barriers. The walk does not consult current switch state and does not apply `Block.allowed_travel_directions`; callers that need direction filtering use `find_ordered_walk` / `query_graph_walks` instead. Used by the route editor's feasibility highlighting and the dispatcher's reachability queries.
  - the `GraphWalkCandidate` table above as the only candidate payload contract.
- Once that shared graph home is in place, every layer that needs pathfinding migrates to it: `RouteExecutor` platform-end selection, `PathDispatcher.create_path(...)` start-side and forward candidate selection, `PathDispatcher.extend_path(...)` suffix selection, and the boundary-projection helpers all share this single home. The legacy block-to-block `PathDispatcher.find_paths(...)` contract is removed or made a thin adapter over the new graph query in v1; it must not remain as a parallel source of operational path choices.
- The implementation must use the following function table as the canonical operational pathfinding surface. If the shared graph home is implemented as methods on `PathDispatcher` rather than an extracted `RailwayPathfinder` class, keep the inputs/outputs and single-home rule identical.

  | Function | Inputs | Output | Required callers / need | Current nearby implementation |
  | --- | --- | --- | --- | --- |
  | `RailwayNetwork.get_connection_edges(tile_a, tile_b)` | adjacent tile coordinates | `Optional[Tuple[str, str]]` edge on `tile_a`, edge on `tile_b` | `TrainPhysics.tick(...)`, graph traversal, directed frame construction | Current code has `RailwayNetwork.get_neighbor(...)` plus `TrackSegment.edges`; no single helper currently returns both edges |
  | `RailwayPathfinder.query_graph_walks(request)` | `request: GraphWalkQuery` | `List[GraphWalkCandidate]` sorted/comparable by candidate metrics | `RouteExecutor` platform-end selection, `PathDispatcher.create_path(...)` start-side selection, `PathDispatcher.create_path(...)` candidate selection, `PathDispatcher.extend_path(...)` suffix selection | Closest backend code is `PathDispatcher.find_paths(...)`, `PathDispatcher._bfs_find_paths(...)`, `PathDispatcher._find_extension_paths(...)`, and `PathDispatcher._bfs_find_extension_paths(...)`; these must be extended/extracted. `static/js/pathfinders.js` has `ConstructionPathfinder.findPath(...)` and `ExistingTrackPathfinder.findPathOnExistingTracks(...)`, but those are editor/construction helpers and are not the runtime operational home. |
  | `RailwayPathfinder.find_ordered_walk(...)` | Same as `RailwayPathfinder.query_graph_walks(...)` plus selection policy when needed | `Optional[GraphWalkCandidate]` chosen by canonical comparison | Thin convenience adapter for callers that need one chosen walk rather than all candidates | No exact current equivalent; closest is `PathDispatcher.find_paths(...)[0]` after sorting, but that lacks new frame semantics |

**Manual mode and movement-authority boundary**

- In `simulation` submode, the driver should call `set_handle()`, the controller should store `handle_position`, and `TrainPhysics` should integrate it into speed while ATC can still override with braking.
- In `power_percent` submode, the driver should call `TrainController.commands.set_manual_power_percent()`, the controller should store `manual.manual_power_percent`, and `TrainPhysics` should convert it through `SpeedProfile.power_speed_curve` in the same tick whenever no braking override is active.
- In that same `power_percent` submode, the converted power-percent command is the absolute voltage/speed command and overrides the normal acceleration/deceleration-rate fields while no safety braking override is active. `TrainPhysics.tick(...)` must set the `span_update.current_speed_kmh` for that tick to the calibrated speed implied by `manual.manual_power_percent`; the model assumes negligible momentum under direct voltage control, so there is no service-rate ramp between manual power-percent settings. Service braking and EB do not use a handle-based braking flow in `power_percent` submode: when controller safety logic requests braking (ATC override, service braking, or EB), the controller forces `manual_power_percent = 0` for that tick (with EB additionally engaging `eb.active`), and physics applies the calibrated zero-speed/zero-voltage outcome from `power_speed_curve`. There is no signed negative power-percent command.
- In manual mode with a received path plan, add `ATCComputer.calculate_authority_boundary_limit()` so the controller brakes to the current authority end boundary using the controller safety margin.
- Without a received path plan, manual mode receives the same no-authority empty lookahead defined in step `22a9` (`atc_limit = 0` at distance 0, `atc_limit_reason_code = no_authority`). There is no fallback to the current-block boundary; if a manual-mode train is rolling when authority is removed, the ATC overspeed branch escalates to EB per step `826a`.

**Completion ownership and timing**

- Make `TrainController` the sole owner of post-physics usable-authority stop interpretation and `PathDispatcher` the sole owner of path completion commit. The controller exposes whether the train is now stopped at the usable end of live authority; dispatcher decides whether that completed stop applies to the active path and then mutates path/resource/route state.
- Let `TrainController` react to dispatcher-committed completion through `on_path_complete()`, but stop letting the controller decide independently that a path-backed run is complete.
- Keep `PathDispatcher` as the sole owner of the `Path` record underlying `TrainController.path_projection.received_path_plan`; `on_path_complete()` is a reaction hook, not an authority-mutating hook.
- Tighten the invariant so path completion is emitted only after the train has already moved for that tick, the post-physics controller stop check says the train is now stopped at the usable end of live authority under the canonical usable-authority stop predicate, and `PathDispatcher.try_complete_active_path(train_id)` accepts it for the active path by verifying both that `Path.authority_end_block_id == Path.requested_destination_block_id` and that the terminal authority traversal direction equals `Path.requested_destination_direction`. The controller safety margin remains a braking/diagnostic target; it is not a separate centimeter-tolerance completion gate.

**Controller invariants**

- There should be no `self.target_speed` field once lookahead-at-distance-0 becomes the canonical source of target speed.
- Controller-owned live control/physical state and train-owned persistent/configuration state should be cleanly separated.
- Controller ATO destination state comes exclusively from `received_path_plan`; there is no fallback read against `Train`.
- `SimulationController.get_or_create_controller(train_id)` should preserve the 1:1 train/controller pairing without recreating authority from train-side runtime mirrors. Its job is only "make sure a controller object exists and is registered for this `train_id`." In v1, controller existence is a hard precondition for any dispatcher path creation/extension: callers must ensure the controller exists before `create_path(...)` or `extend_path(...)`. `SimulationController` must not construct or write a path payload itself, and there is no late-bind recovery hook such as `PathDispatcher.on_controller_available(train_id)` — `received_path_plan` is a property that resolves live, so no late controller write is needed.
