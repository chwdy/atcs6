## Block

**Block model**

- `Block` is a `TrackResource` subclass; the shared identity surface (`resource_id`, `resource_type == "block"`, `name`, `occupied_by`, `disabled`) comes from the **TrackResource** canonical home. Block-only fields below extend that base.
- Replace the stored `state: BlockState` field with the following underlying primitive fields and make `state` a computed read-only property:
  - `occupied_by: Optional[str]` — physical train presence (non-None means a train is in the block).
  - `caution: Optional[CautionState]` — physical safety-margin record. `None` when not in caution. `CautionState` carries exactly `exit_edge: "N" | "E" | "S" | "W"` (the departing train's exit edge). The two-field unit is always written together by `BlockManager.on_block_tail_vacated()` and cleared together by `_reevaluate_caution_blocks()` or `release_path_block_reservations(completed=True)`, so storing them as one Optional record makes the all-or-nothing rule structural rather than enforced by prose. Convenience reads `_is_caution` (= `caution is not None`) and `caution_exit_edge` (= `caution.exit_edge` or `None`) may still be referenced by name throughout this document for readability.
  - `reservation: Optional[BlockReservation]` — the one active path's dispatcher reservation on this block, or `None` when no path holds it. `BlockReservation` carries exactly `path_id: str` (which active path holds the reservation), `train_id: str` (the train the reservation is intended for; separate from `occupied_by` so that `BlockManager.occupy_blocks()`'s RESERVED-entry safety check stays effective after `occupied_by` is removed from the RESERVED state), and `exit_edge: "N" | "E" | "S" | "W"` (the direction reserved by the dispatcher through the block). The three fields are always written together by `BlockManager.reserve_blocks_for_path(...)` and cleared together by `Block.release_path_reservation()`/`occupy_blocks(...)`, so storing them as one Optional record makes the all-or-nothing rule structural rather than enforced by prose. Convenience reads `reserved_by_path`, `reserved_for_train`, and `reserved_direction` are derived from `reservation.path_id`, `reservation.train_id`, and `reservation.exit_edge` respectively (each `None` when `reservation is None`); they may still be referenced by name throughout this document for readability.
  - `disabled: bool = False` — static availability flag. A disabled block cannot be used as a direct waypoint/stop target, cannot be reserved or occupied in normal runtime flow, and pathfinding/wayfinding treats it as absent connectivity.
  - `allowed_travel_directions: Set["forward", "reverse"]` — static block-level travel policy for this block. Defaults to both directions allowed. This is not a reservation field and is not stored on `TrackSegment`; `Block.reserved_direction` remains only the temporary dispatcher reservation direction for one path.
- The computed `state` property should use priority order: OCCUPIED > CAUTION > RESERVED > FREE.
  - Return `OCCUPIED` if `occupied_by is not None`.
  - Return `CAUTION` if `caution is not None`.
  - Return `RESERVED` if `reserved_by_path is not None`.
  - Return `FREE` otherwise.
- The intended computed-state table is:
  - physical `occupied_by is not None` -> `OCCUPIED`
  - physically free + `caution is not None` -> `CAUTION`
  - physically free + not caution + `reserved_by_path is not None` -> `RESERVED`
  - physically free + not caution + not reserved -> `FREE`
- This makes composite physical+reservation states directly representable without contradictions:
  - OCCUPIED + `reserved_by_path` set (start-block scenario): `state` reads `OCCUPIED`; reservation is visible and clearable as a plain field write with no state check.
  - CAUTION + `reserved_by_path` set (path holds block through safety margin): `state` reads `CAUTION`; reservation is likewise clearable unconditionally.
- Treat `reserved_by_path` as the dispatcher's resource lock and `occupied_by` as physical train presence only.
- `occupied_by` should always be `None` in `RESERVED` and `CAUTION`; the dispatcher sets `reserved_by_path`, not `occupied_by`, to claim a block.
- `Block.ordered_tiles` is the canonical block-local traversal order, and `Block.allowed_travel_directions` is the static allowed-direction policy. The list index is the canonical block-local traversal index. It is initialized from the tile list supplied to backend block-creation/edit logic, preserved through block edits, and never rewritten by runtime switching or path acquisition. Backend validation must verify the supplied list is already one connected switch-free walk in that exact order; it must not reorder, reverse, or silently renormalize the caller-supplied sequence. Block edits may only insert or remove member geometry at the ends while preserving relative order; middle insertions, reorders, or reversals are rejected by backend edit validation. For a direct block target, `requested_destination_direction == "forward"` means movement in the increasing direction of `ordered_tiles`, `"reverse"` means the decreasing direction. Before `RouteExecutor` or `PathDispatcher` accepts the request, the concrete `"forward"` or `"reverse"` value must be present in the target block's `allowed_travel_directions`.
- `Block.ordered_tiles[0]` is the canonical local index-0 tile; v1 does not add a second stored "index-0 tile" field. Each entry in `Block.ordered_tiles` carries `(x, y, entry_edge)`, where `entry_edge` is the external edge through which forward traversal enters that tile. The forward-entry anchor for the block is therefore `Block.ordered_tiles[0].entry_edge`; no separate field is stored. The forward exit edge is not stored on the entry because it is determined by connectivity to the next tile in the ordered list (or, for the terminal tile, by the block's external boundary toward the next block).
- The canonical local-direction anchor table is:

| Field | Type | Required | Meaning |
| --- | --- | --- | --- |
| `ordered_tiles` | ordered list of `(x, y, entry_edge)` entries | yes | Canonical local block order; `ordered_tiles[0]` is local index `0` and its `entry_edge` is the forward-entry anchor for the block |

- The canonical block-direction helper uses `Block.ordered_tiles` adjacency to derive traversal frames in multi-tile blocks and reads `Block.ordered_tiles[0].entry_edge` for single-tile blocks, same-tile ambiguity resolution, and validation.
- Because acquisition decisions need to check all blocks at once, `BlockManager` should be the sole mutator of Block runtime state (`occupied_by`, `_is_caution`, `reservation`); `Block` should remain a data container. Block geometry / topology mutation (`length_cm`, `speed_limit_kmh`, `ordered_tiles`, plus `track.block_section_id` writes during block create / extend / delete / split) lives in a separate `BlockGeometryManager` (file `block_geometry_manager.py`). `RailwayNetwork.create_block / create_block_with_tracks / extend_block / delete_block / assign_track_to_block / validate_block_continuity / remove_tile_from_block / remove_tiles_from_block` are doc-canonical method names but are now implemented as forwarders to `BlockGeometryManager`. The two managers have disjoint write surfaces: `BlockManager` for runtime state, `BlockGeometryManager` for geometry / topology.
- There is no admin-side direct-mutation surface for Block state. The pre-v1 `RailwayNetwork.set_block_state(block_id, state)` and `cycle_block_state(block_id)` shims were removed in PR 6; calling them tried to assign `block.state` (a read-only computed `@property`) and raised `AttributeError`. v1 owns block state through `BlockManager` / `ResourceCoordinator`; admin endpoints that wanted to drive block state for testing must instead drive it through real flows (place a train, create a path, etc.) so the canonical writers run. The `POST /api/blocks/<block_id>/cycle-state` endpoint that exposed the shim is also gone; the `PATCH /api/blocks/<block_id>` endpoint rejects `state` mutations with HTTP 410.

**`CAUTION` vs reservation independence**

- `CAUTION` is an independent safety state indicating the block ahead (in the departing train's direction) is still occupied; it is orthogonal to path reservation.
- A block can be simultaneously `CAUTION` and `reserved_by_path` (path still holds it for a future or in-progress train), or `CAUTION` with no reservation (train has passed and path is done). With the computed-state model both combinations are natively representable — the `state` property returns `CAUTION` in both cases, and `reserved_by_path` can be cleared by a plain field write with no state guard.
- `CAUTION` by itself does not make a block unreservable. Its operational effect is that `TrainController` lookahead applies `CAUTION_SPEED_LIMIT_KMH` when it samples the block. `BlockManager.reserve_blocks_for_path(...)` must still allow a `CAUTION` block when the primitive reservation predicate below is satisfied.
- Runtime physical entry into a disabled block is not a normal recoverable workflow. `BlockManager.occupy_blocks(...)` must report it through the fatal physical-entry conflict procedure with `conflict_kind = FatalConflictKind.DISABLED_RESOURCE_ENTRY`; it must not silently mark the disabled block occupied. Operator/admin code must reject disabling a block that is physically occupied, reserved, or in `CAUTION`. v1 has no force-cleanup workflow that bypasses those claims; the operator/admin must remove the conflicting train, cancel the holding path, or wait for `CAUTION` to clear through the ordinary runtime workflows before the disable request is accepted.
- The `OCCUPIED → CAUTION → FREE` lifecycle is driven purely by physical train movement through `BlockManager`; it does not depend on whether a path reservation exists.
- Path reservation (`reserved_by_path`) is consumed by the dispatcher/manager on train-head entry into that block, or released by the dispatcher on path completion/cancellation if the block was never entered. This is separate from the occupancy state machine.
- `CAUTION` is directional: `block.caution.direction` records the direction the departing train was moving. The `CAUTION → FREE` check must only look at the adjacent block in that direction, not at all neighbours, and it must read the occupying train's current `travel_direction` when that adjacent block is `OCCUPIED`. Two cases follow from this rule. A following train entering the block immediately behind never participates in the check because it is not the forward neighbour, so it cannot incorrectly keep a `CAUTION` block alive. And on the forward side, an `OCCUPIED` neighbour holds `CAUTION` in place only while its train is still moving away in the protect direction — i.e. its `travel_direction` matches `block.caution.direction`. Once that train flips its cab so its `travel_direction` is the opposite of `block.caution.direction`, it is no longer moving away from the `CAUTION` block; the protection chain is stale and the `CAUTION` block clears.

**Block methods**

- Path reservation and physical occupancy are separate concerns: reservation eligibility is checked in `BlockManager.reserve_blocks_for_path(...)`; `BlockManager.occupy_blocks([block_id], train_id)` records physical train entry only (single-block calls go through the same atomic helper with a one-item list). `BlockManager` is the sole mutator for both physical and CAUTION transitions.
- `Block.reserve_for_path(path_id, train_id, direction)` is an internal helper called only by `BlockManager.reserve_blocks_for_path(...)`. It writes `block.reservation = BlockReservation(path_id=..., train_id=..., exit_edge=...)` (the derived `reserved_by_path`, `reserved_for_train`, and `reserved_direction` reads all become defined together). The `direction` argument may be a compass `exit_edge` (`"N" | "E" | "S" | "W"`) or a block-relative `"forward"` / `"reverse"`; the block converts via `Block.ordered_tiles` adjacency (multi-tile) or `Block.ordered_tiles[0].entry_edge` (single-tile) and stores the compass `exit_edge` in `block.reservation.exit_edge`. The reservation never overwrites `occupied_by` (which stays physical-only).
- `Block.release_path_reservation()` is an internal helper called only by `BlockManager.release_path_block_reservations(...)`. It clears `block.reservation` (so the derived `reserved_by_path`, `reserved_direction`, and `reserved_for_train` reads all become `None` together) with no state guard. It must NOT touch `block.caution` (that field is the physical-lifecycle owner's, `BlockManager`).

**Block invariants**

- `BlockManager.occupy_blocks(block_ids, train_id)` is the sole physical-entry writer (no separate single-block method). Clean entry sets `block.occupied_by = train_id`, clears `block.caution = None`, and consumes any same-train reservation by clearing `block.reservation` (the derived convenience reads `reserved_by_path`, `reserved_direction`, and `reserved_for_train` all become `None` together). If a target block is already occupied by another train or reserved for another train, `occupy_blocks(...)` reports the canonical unrecoverable hard-failure path by sending a typed `FatalPhysicalEntryConflict` to `SimulationController.enter_failed_runtime(...)`. It must not silently overwrite a prior owner. `OCCUPIED` overrides `CAUTION` on clean entry; stale caution metadata must not survive an intervening clean entry. Returns `OccupyResult(outcome: str, reason: Optional[str])` where `outcome` is one of the free-form strings `"clean_entry"`, `"idempotent_noop"` (block already occupied by this same `train_id`), or `"fatal_conflict"`. When `outcome == "fatal_conflict"` the method has already invoked `SimulationController.enter_failed_runtime(...)` as a side effect; the caller checks the outcome and stops processing. The method always returns; no exception or short-circuit.

## BlockManager

**Block-manager model**

- `BlockManager` should become the database-style lock manager for block resources and the single serialization point for atomic block acquisition, whether the dispatcher is attempting a full-route all-or-nothing reservation or a best-effort prefix reservation.
- `BlockManager` holds both the owning `RailwayNetwork` entity layer and an `Optional[SimulationController]` runtime back-reference. It uses the network for block/switch registries and topology reads; it uses the runtime surface only to report unrecoverable fatal physical-entry conflicts through `SimulationController.enter_failed_runtime(...)`. `SimulationController`, not `BlockManager`, owns the failed-runtime flag, runtime freeze, stored fatal payload, and release-after-manual-cleanup gate. Fatal conflict handling itself does not perform route/controller/path teardown; any later train removal or resource repair is an explicit manual/admin cleanup workflow.
- Keep `occupy_blocks(block_ids, train_id)` as the existing atomic occupy helper.
- Define `ReservedBlockTraversal` as the canonical value type for `directions` in `BlockManager.reserve_blocks_for_path(...)`. It carries exactly `exit_edge` (`"N" | "E" | "S" | "W"`) and `block_direction` (`"forward" | "reverse"`). `block_direction` is derived canonically from the block's immutable internal tile order: if the directed in-block traversal advances to higher indices in `Block.ordered_tiles`, it is `"forward"`; if it advances to lower indices, it is `"reverse"`; if the traversal stays within one ordered tile, use the chosen entry's explicit directed frame for that tile rather than train-end labels.
- Add `reserve_blocks_for_path(block_ids, path_id, train_id, directions)` to replace one-by-one block reservation with atomic reservation.
- `directions` in `reserve_blocks_for_path(block_ids, path_id, train_id, directions)` should be a mapping keyed by `block_id`, where each value is one `ReservedBlockTraversal`. `PathDispatcher` owns building that mapping from the chosen path geometry before calling `BlockManager` and must use the same canonical block-direction helper used by route callbacks. `ReservedBlockTraversal.exit_edge` is written to `block.reservation.exit_edge` (read as `Block.reserved_direction`); `ReservedBlockTraversal.block_direction` is used only for `Block.allowed_travel_directions` validation.
- `reserve_blocks_for_path(...)` must first check eligibility for every future block in the candidate block set before writing any fields. Blocks already physically occupied by the train may appear in `Path.resource_sequence` for geometry/progress, but they are not included in the future reservation candidate set. A candidate future block is eligible when `block.disabled == False`, `block.occupied_by is None`, `block.reserved_by_path is None or block.reserved_by_path == path_id`, and the candidate `ReservedBlockTraversal.block_direction` is present in `block.allowed_travel_directions`. `block.caution is not None` is not an eligibility failure by itself; `CAUTION` affects the following train through `TrainController.CAUTION_SPEED_LIMIT_KMH`, not by blocking an otherwise legal reservation. If any block in that candidate set fails eligibility the entire call is rejected and no state changes are made. `PathDispatcher` owns choosing whether that candidate set is the full requested route (`all_or_nothing`) or the longest best-effort prefix it wants to attempt atomically.
- `reserve_blocks_for_path(...)` writes the reservation atomically by calling `Block.reserve_for_path(path_id, train_id, reserved_exit_edge)` with the mapping value's `exit_edge` for each future block; the helper sets `block.reservation` in one step (the derived `reserved_by_path`, `reserved_for_train`, and `reserved_direction` reads all become defined together). It must not create path-owned reservations for blocks the train already physically occupies; those resources are train-owned physical occupancy and are represented only in `resource_sequence` / `current_resource_index` for path progress. Returns `ReserveResult(success: bool, failed_block_id: Optional[str], reason: Optional[str])`. On success all reservations are written atomically; `failed_block_id = None`. On failure no field is mutated, `failed_block_id` is the first block that failed eligibility, and `reason` is a free-form diagnostic string.
- Add `release_path_block_reservations(block_ids, path_id, completed=False)` to release not-yet-entered reservation ownership; it replaces scattered direct `block.release()` calls during completion and cancellation without modifying physical occupancy state. This manager method must clear only blocks that both belong to that path's dispatcher-owned future reservation set and currently satisfy `block.reserved_by_path == path_id`; a mismatched block is ignored and must emit a `NotificationCenter` diagnostic such as `release <block_id> but it's not reserved for <path_id>` rather than being treated as a hard release failure. Because `Block.release_path_reservation()` is now a plain field clear with no state guard, this method can call it for each matching owned block regardless of whether the block is currently `CAUTION` or `RESERVED`; normal head-entry consumption means occupied resources should no longer be path-owned future reservations. When `completed=True` (path completed with train fully stopped at terminal), it additionally force-clears `block.caution = None` on any still-CAUTION matching owned blocks. When `completed=False` (path cancelled mid-flight), physical CAUTION state is left untouched — the train is still moving and the safety margin must be preserved. Returns `bool`: `True` if at least one matching reservation was released; `False` if none.
- `on_block_tail_vacated(block_id, train_id, direction)` is the canonical tail-vacate entry: it clears `block.occupied_by`, sets `block.caution = CautionState(direction=direction)`, then calls `_reevaluate_caution_blocks()` to cascade any blocks that can already advance to `FREE`. Returns `bool`: `True` on a clean tail-vacate; `False` on the no-op cases (missing block in registry, mismatched owner — see invariants below). No exception raised.
- Treat `on_block_tail_vacated()` as the only normal train-vacated physical transition entry point.
- Keep `release_path_block_reservations(...)` as future-reservation release for path completion and cancellation. Head-entry consumption of a block reservation happens through the physical-entry path, not this path-release path.
- `BlockManager.release_path_block_reservations(block_ids, path_id, completed=False)` is the single canonical reservation-release entry point — used for both routine path completion/cancellation release and manual/admin reservation cleanup. Operator/admin cleanup callers pass the affected block IDs and the matching `path_id`; the method clears `block.reservation` only on blocks where `block.reservation is not None and block.reservation.path_id == path_id` (so the derived `reserved_by_path`, `reserved_direction`, and `reserved_for_train` reads all become `None` together), never touches `occupied_by` / `caution` outside the existing `completed=True` exception, and emits a diagnostic for mismatched blocks. Manual/admin cleanup must not bypass this entry point.
- `BlockManager` should read block/switch registries from the owning `RailwayNetwork` entity layer rather than maintaining its own copied block/switch registries. `RailwayNetwork` remains the canonical home of the block registry, switch registry, and topology graph/traversal helpers. `BlockManager` reads `network.blocks`, `network.switches`, and one shared network-topology adjacency helper from there; it must not rescan unrelated entity lists or invent a second topology cache of its own.

**`on_block_tail_vacated()` behaviour (directional CAUTION evaluation)**

- `TrainController.on_physics_updated(span_update)` reports normal tail-vacated block resources through `PathDispatcher.on_controller_progress(report)`, which routes the release through `ResourceCoordinator.release_tail_vacated(...)`; the coordinator is the only normal runtime caller that invokes `BlockManager.on_block_tail_vacated(block_id, train_id, direction)` for block resources. `TrainPhysics` does not call `BlockManager` directly.
- `BlockManager` does not independently decide that a block resource should be released; that instruction comes from `PathDispatcher.on_controller_progress(report)` after a controller-reported tail-vacate observation. For normal runtime release, `train_id` must still match the current physical owner. If `block_id` is not present in the `BlockManager` registry (e.g. during early bootstrap or after teardown), `on_block_tail_vacated()` is a no-op success: it returns without emitting a diagnostic. If the block exists but `block.occupied_by != train_id`, `on_block_tail_vacated()` must leave the block unchanged and emit a `NotificationCenter` diagnostic such as `block <block_id> release for train <train_id> skipped: currently occupied by <other_train_id>`.
- `BlockManager.on_block_tail_vacated(block_id, train_id, direction)` is one-shot: the controller-reported tail-vacate observation only fires the tick a tile is removed from the train span. If `block.occupied_by != train_id`, the diagnostic emits exactly once for that `(train_id, block_id)` and is not retriggered, because subsequent ticks will not re-report the same removed tile.
- `BlockManager.on_switch_position_changed(switch_id)` is safe to call once `BlockManager` is constructed, even before any blocks/switches have been registered. Empty-registry calls are a no-op.
- `direction` on `on_block_tail_vacated(block_id, train_id, direction)` is the vacated block's forward `exit_edge` (`N`/`E`/`S`/`W`) for the traversal by which the train left that block.
- If `block.occupied_by == train_id`, `on_block_tail_vacated()` clears `block.occupied_by` and sets `block.caution = CautionState(direction=direction)`. With the computed-state model the block's `state` property now returns `CAUTION`.
- After updating the vacated block, `BlockManager` should call `_reevaluate_caution_blocks()` to cascade any blocks that can already advance to `FREE`.
- `_reevaluate_caution_blocks()` iterates all blocks currently in `CAUTION`. In the normal reevaluation path, a `CAUTION` block advances to `FREE` unless the forward protection chain is both reachable AND ends in an `OCCUPIED` block whose train is still moving away in the protect direction. `BlockManager` owns this walk, but it performs it through the shared `RailwayNetwork` topology graph / neighbour-traversal helper rather than by scanning the full entity lists. "Forward block" is defined precisely: start from the vacated block's exit edge for `block.caution.direction`, inspect the neighbouring resource in network connectivity, and keep following live tile connectivity through any intervening switch tile using the current `Switch.position` until the next block resource is reached. That next reachable block resource is the only block consulted for the `CAUTION -> FREE` decision; blocks behind the vacated block or off the currently selected switch branch are ignored. When that block is `OCCUPIED`, `BlockManager` reads the occupant train's current `travel_direction` through its `SimulationController` back-reference (via `SimulationController.get_controller(train_id).travel_direction`) and keeps `CAUTION` only when that direction equals `block.caution.direction`; an opposite `travel_direction` means the train has flipped its cab and is no longer moving away, so the `CAUTION` block clears. This shape prevents a following train (entering from behind) from keeping a caution block alive, lets a later switch throw invalidate the old protected chain, and lets a same-train cab flip retire the now-stale safety margin on the side the train has just reversed away from.
- If `_reevaluate_caution_blocks()` cannot resolve any reachable forward-adjacent block in `block.caution.direction`, if live connectivity no longer reaches the block that was previously being protected, or if the `OCCUPIED` forward block holds a train whose current `travel_direction` is the opposite of `block.caution.direction`, there is nothing ahead left to protect. In that case it should clear `block.caution = None` immediately, so the computed state becomes `RESERVED` if `reserved_by_path` is still set, otherwise `FREE`. When `BlockManager` has no `SimulationController` back-reference wired (early bootstrap, unit tests that exercise `BlockManager` in isolation), or when the occupant train's `travel_direction` cannot be resolved, the reevaluator preserves the existing `CAUTION` state — the clear requires positive evidence of reversal, not absence of evidence.
- When a CAUTION block clears, set `block.caution = None`. The block's computed `state` then re-evaluates to `RESERVED` if `reserved_by_path` is still set, or `FREE` if it is not.
- Reevaluation is triggered by manager-owned connectivity changes, not by a periodic scan: at minimum `BlockManager.on_block_tail_vacated()` must call `_reevaluate_caution_blocks()`, and every successful `BlockManager.on_switch_position_changed(switch_id)` call must also trigger `_reevaluate_caution_blocks()`. `Switch` does not independently clear block caution state; it only changes connectivity, and `BlockManager` remains the sole owner of the actual `CAUTION -> FREE` decision.
- `reserved_by_path` is NOT checked as a condition for `CAUTION → FREE`. The physical safety margin and the dispatcher reservation are independent: a block can become physically clear of `CAUTION` while still holding a `reserved_by_path` value. In that case the computed `state` becomes `RESERVED`, not `FREE`, until the dispatcher separately clears the reservation via `release_path_block_reservations()`.
- Explicit exception: `BlockManager.release_path_block_reservations(..., completed=True)` may force-clear `block.caution = None` during terminal completion release for owned blocks. That is a completion-time release rule, not part of the normal neighbour-based reevaluation path.
