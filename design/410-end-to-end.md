## End-To-End ATO Path Run

**End-to-end path-authority projection**

- `PathDispatcher` stores the active dispatcher-owned `Path`; `TrainController.path_projection.received_path_plan` reads the canonical **received_path_plan schema** projection from that active record. `controller.assigned_path_id` is a derived read of that projection's `path_id`.
- `RouteExecutor` should ensure the train's `TrainController` exists before path authority is created or extended in Phase 1.
- `RouteExecutor` should not write `assigned_path_id` or `ato_destination_block_id` directly.

**End-to-end ATO run**

This is a high-level walk-through; canonical contracts live in the relevant sections (see **Active-path completion procedure**, **Planning Kernel**, **Route-run state**, **Phase Table**).

1. Phase 1: covered-task index advance, resolve the next task via `_find_next_task_target(train_id)` to get one concrete `(requested_destination_block_id, requested_destination_direction)`, and call `PathDispatcher.create_path(...)` (or `extend_path(...)` if a live path exists), using `acquisition_mode = route.acquisition_mode`. If a resolved pass-through (`waypoint`) target block is already covered, the index advance skips it; if a resolved stop target block is already covered, the stop remains the current target and uses ordinary same-block stop authority/completion.
2. Phase 2: controller lookahead / ATC / ATO command generation, then physics integrates and emits boundary-by-boundary `PhysicsSpanUpdate` callbacks.
3. Phase 3: drain the same-transaction local progress buffer (movement-derived cancellation commits inline); run the post-physics usable-authority stop check; on success call `PathDispatcher.try_complete_active_path(train_id)` per the **Active-path completion procedure**; then `pending_path_cancel_request`, `pending_route_abort`, `pending_power_off`, and `pending_route_deactivate` in the canonical order. `pending_path_cancel_request` consumption (and any latch that depends on it via the inclusive-latch rule) is gated by `TrainController.is_stopped() == True`. (Dwell-complete, route-deviation cleanup, and terminal route completion are Phase 1 steps on the next eligible tick, not Phase 3.)
4. Best-effort retries call `PathDispatcher.extend_path(...)` on the same `path_id` until the live authority reaches the requested target. `blocked_no_growth` keeps the live path; structural `failure_kind` (`no_viable_path`, `invalid_reverse`) latches cancel and triggers cancel-and-replan.
5. Stop arrival records `finished_at` for the stop task. The next tick's Phase 1 dwell-entry step inside `RouteExecutor.tick_train_phase1(...)` transitions the controller to `RUNNING_AT_STATION` automatically when the route's next task is `dwell`. Phase 1 dwell-complete steps `RouteTask.should_depart(...)`, calls `TrainController.finish_dwell()`, and sets the dwell task's `finished_at`, which makes the derived `current_waypoint_index` advance. It then either removes the route run if no tasks remain or leaves the next target to a later Phase 1.

**End-to-end manual-arrival note**

- Manual trains use the same dispatcher-committed arrival and Phase 1 dwell-entry step inside `RouteExecutor.tick_train_phase1(...)` as ATO trains. The only difference is departure behavior: in manual mode `TrainController.depart()` marks the current authority ready to go and does not call `TrainController.ato.go()` or start movement by itself.

**End-to-end post-EB restart note**

- EB recovery follows the canonical EB workflow state machine below. The pre-EB path is never reused; after EB release, the next eligible Phase 1 creates fresh authority and calls `TrainController.depart()` directly per the canonical depart contract.

**EB workflow state machine**

This is the single canonical step-by-step contract for EB activation, release, and post-EB restart in v1. Shared contracts must not invent separate EB-recovery state flags on `TrainController` or `RouteExecutor` beyond the ones listed below.

**Canonical EB activation effects** (referenced elsewhere by name): Sets `eb.active = True`, forces handle to `EB`, clears `ato.running = False`, and records `pending_path_cancel_request` with `initiator = "eb"` if a live path exists. Other sites must cross-reference this paragraph by name and must not restate the effect list.

| Step | Trigger | Actor | Effect |
| --- | --- | --- | --- |
| 1 (`4c64`). EB activation | ATC overspeed escalation (including the no-authority overspeed branch in step `826a` where `received_path_plan` has gone `None` while the train is still rolling) or operator-issued `TrainController.eb.activate()` | `TrainController.tick()` (Phase 2) for all EB paths: operator-issued EB is accepted during the tick-entry command drain, while ATC / no-authority EB is raised later in the same tick call | Performs the **canonical EB activation effects** above, then enters the early-exit tick loop. The same train's later Phase 3 consume pass commits that cancellation through `PathDispatcher.cancel_path(...)` once the train has stopped (per the gating in the Latch Table); if the active path was already cleared earlier in the same Phase 3 pass, the dispatcher cancel mutation is skipped per the **Phase-3 latched-cancel consumption when no active path** rule and the latch is still consumed (controller-local EB state stays owned by the EB workflow). Ordinary tick work is skipped until the train stops and EB is released. |
| 1a (`0a8e`). EB activation while dwelling | `TrainController.eb.activate()` is accepted while `state == RUNNING_AT_STATION` | `TrainController.tick()` (Phase 2) | Sets `eb.active = True`, forces handle to `EB`, and does NOT write `pending_path_cancel_request` (no live path during dwell). State stays `RUNNING_AT_STATION`. Dwell timer (`task_runs[walk_position].started_at` with `task_kind == "dwell"`) is unaffected; dwell continues to count toward `RouteTask.should_depart(...)`. No deviation/cancellation effects fire. |
| 2 (`e67d`). Rolling stop under EB | Physics integrates EB deceleration | `TrainPhysics.tick()` | Train decelerates according to `SpeedProfile.emergency_brake_rate`; `current_span` and `current_speed_kmh` continue to update normally. No additional authority completion/cancellation side effects fire during rolling beyond the earlier EB-cancellation request, but physics remains authoritative: `TrainPhysics.tick(...)` continues emitting span updates, and the same train's Phase 3 consume pass continues committing physical entry and tail-vacate resource updates while EB is latched. |
| 3 (`9f74`). Full stop under EB | `TrainController.is_stopped()` returns `True` | `TrainController.tick()` | Controller remains in the EB early-exit loop with `eb.active == True`; no state transition yet. Dispatcher path completion is explicitly suppressed while `eb.active == True`. |
| 4 (`ad04`). EB release | `TrainController.eb.release()` called while stopped and powered after the EB cancellation latch has been consumed (controller's own `pending_path_cancel_request` is `None`) and dispatcher has transitioned the pre-EB active path out of `ACTIVE` (controller's own `received_path_plan is None`) | operator | Clears `eb.active = False`; transitions controller to `READY`. If the EB cancellation is still pending or the old live path still exists, the release command fails through `NotificationCenter` and does not transition state. `TrainController.eb.release()` does not call `RouteExecutor`, does not inspect or complete the cancelled pre-EB path, and does not clear route-owned recovery state itself. |
| 4a (`1bbc`). EB release from dwell | `TrainController.eb.release()` called while `state == RUNNING_AT_STATION`. The acceptance gate (`pending_path_cancel_request is None`, `received_path_plan is None`, `is_stopped() == True`) is naturally satisfied because no live path was cancelled by the dwell EB and the dwelling controller has speed `0`. | operator | Clears `eb.active = False`; state stays `RUNNING_AT_STATION`; dwell timer is unaffected. No EB-specific restart/replan is needed for this branch — row `29a0` does not apply to the dwell EB cycle. |
| 5 (`29a0`). EB restart/replan | `RouteRun.path_cancelled == True` (set by the EB cancellation callback) AND `controller.is_recovery_clean` is true on the next eligible `RouteExecutor.tick_train_phase1(...)` | `RouteExecutor.tick_train_phase1(...)` (Phase 1) | The Phase 1 route-deviation-cleanup step clears `RouteRun.path_cancelled` when a route run exists, so the derived diagnostic status returns to `RUNNING`. The same Phase 1 then continues into the ordinary planning kernel: covered-task index advance → `_find_next_task_target(train_id)` → fresh `PathDispatcher.create_path(...)` → `TrainController.depart()` per the canonical depart contract. |

- `eb.active` is controller-owned, but EB activation must request dispatcher cancellation through `pending_path_cancel_request` immediately when a live path exists. The actual cancellation side effects still run only inside `PathDispatcher` during the same train's later Phase 3 consume pass; `TrainController` never releases resources itself.
- EB recovery uses the same recovery latches as any other cancellation: `RouteRun.path_cancelled` for route-owned recovery cleanup. No EB-specific route hook or auto-depart flag exists in v1.
